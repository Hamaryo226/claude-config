## この run で分かったタスク設計の不備

**`md-style` は `rules/markdown-ja.md` を測れていない。**
成功率は全アーム 100%、日本語表記の違反数は全アーム 15 件で、**fixture の初期値 15 から 1 つも動かなかった**。
指示が「実装と食い違っているコマンド名を直す」なので、正しい最小の修正では
違反のある行 (箇条書きの記号、全角括弧、全角句読点) に触らずに済んでしまう。
`CLAUDE.md` の「依頼された範囲を勝手に広げない」に照らせばモデルの挙動は正しく、
**タスクの側が間違っている。** rules を測るには、モデルに新しく文章を書かせる指示に変える必要がある。

**`commit-skill` は指示が CLI に横取りされていた。**
プロンプトが `/commit` の 1 行だったため、スキルを持たない `a0`-`a2` では Claude Code の CLI が
「Unknown command: /commit」を返して終わり、モデルに何も届いていない (tool call 0 / token 0 / 1 秒)。
同一プロンプトでの比較になっていなかった。この run のあと、
指示を「未コミットの変更を `/commit` の手順でコミットしてください。」に変えた (commit `b0c673c`)。

**`commit-skill` はスキルを持つアームでも成功しない。**
`a3` / `a4` ではスキルが起動し、変更を正しく 2 つに分類したうえで
「`main` は保護ブランチなので作業ブランチを切ることを提案します」と述べて**確認待ちで停止**した。
コミットは 0 件。`/commit` は確認を取る設計なので、無人実行では原理的に完了しない。
これはスキルの欠陥ではなく、ヘッドレス評価とスキルの前提が合っていない。

**`ts-bugfix` は簡単すぎる。** 全アーム 3/3 で成功し、変更ファイルも 1 件で揃った。
`rules/web.md` の差は出ていない。
