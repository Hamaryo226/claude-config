# レポートと rules の生成

## 1. レポート (Phase 5。ファイルを書く前に必ず出す)

```
# Codebase conventions

調査範囲: <モジュール数> / 読んだ代表ファイル <n> 件 / 数えた対象 <glob>

## 明示的設定で強制されているもの
- <項目> — 根拠: <設定ファイル:行>。CI 必須: はい / いいえ

## 強く確認できた規約 (90% 以上)
- Service は `application/service/` に配置 — 根拠: 31/33 Service クラス
- private field は `_camelCase` — 根拠: 42/45 field
- public method に Javadoc を書かない — 根拠: 48/51 method
- コメントは日本語・常体。業務ルールの根拠を分岐の直前に書く — 根拠: 代表 6 ファイル中 6

## 弱い傾向 (70〜90%)
- <項目> — <分子/分母>。例外あり。断定せず「周辺に合わせる」と書く

## 混在しているもの (Rule にしない)
- constructor injection 18 / field injection 17 — 規約として確定できない
- test method naming — `should_xxx` 12 / 日本語 9 / `testXxx` 7

## 新旧で違うもの
- <項目> — 全体 18/17 だが直近 1 年は 15/2。移行中

## 不明
- Utility class を作る基準 — 母数不足 (3 件) で判断できない

## 編集禁止領域
- `<path>` — 生成コード。再生成: `<コマンド>`
```

数字の無い行を書かない。**「不明」を空欄にせず、不明と書く。**

## 2. rules の構成案

**プロジェクトの構造に応じて必要なものだけ。無意味に細分化しない。**

目安:

| 状況 | 構成 |
| --- | --- |
| 単一言語・単一モジュール | `code-conventions.md` 1 枚 |
| バックエンド + フロントエンド | `backend.md` / `frontend.md` |
| テストの流儀が本体と明確に違う | + `tests.md` |
| コメント規約が言語をまたいで共通で、量がある | + `comments.md` |

**分ける理由は `paths` が違うこと。** 内容の見出しが違うだけなら 1 枚にまとめる。
`paths` を書けないものは rules にしない。

各案について次を示す:

```
.claude/rules/<name>.md
  paths: <glob>
  載せる項目: <レポートのどの行か>
  なぜ CLAUDE.md ではなく rules か: <対象が限定されるから>
```

## 3. 既存 `.claude/rules/` がある場合

**上書きしない。** 各ファイルを分類して提示する。

| 分類 | 条件 |
| --- | --- |
| 維持 | 実コードと一致。触らない |
| 追記候補 | 有効だが今回の観測で足りない項目がある。差分を提示 |
| 古い可能性 | 書かれた規約と実コードが違う。**どちらが正しいか決めない**。両方の数字を出す |
| 重複 | CLAUDE.md か他の rules と同じことが書いてある。片方に寄せる案を出す |
| 実コードと矛盾 | 明確に反している。観測値を添えて報告し、判断はユーザーに委ねる |

## 4. rules のテンプレート

**1 ファイル 60 行以内。**超えるならルールを絞る。ファイルを増やして逃がさない。

```markdown
---
paths:
  - "<glob>"
---

# <対象>

## どこに書くか

- <種類> → `<path>` (<分子/分母>)
- 新しい<処理> は <レイヤ> に置く。<レイヤ> から <レイヤ> は参照しない

## 書き方

- <観測できた規約> (<分子/分母>)

## コメント

- <書く場所>
- <書かない場所>   ← 必ず入れる
- 言語 / 文体: <>
- TODO の形式: `<実例>`

## 混在しているもの (統一しない)

- <項目> — 既存コードで割れている。**周辺のファイルに合わせる**
```

書き方の決まり:

- 各ルールに根拠の数字 `(42/45)` を添える。後から検証できるようにする
- 実例をそのまま 1 行貼る方が、説明文より短くて正確なことが多い
- 一般論を混ぜない。1 行足すごとに、既にある行の追従率が落ちる
- **`混在しているもの` の節を省かない。** 「統一しなくてよい」と明示することで、
  Claude が勝手に片方へ寄せる変更を防げる

## 5. 生成後の検算

書いた配置ルールで、実在するファイルのパスが説明できるか 1 件確かめる。
説明できないなら、ルールが間違っているか例外がある。数え直す。
