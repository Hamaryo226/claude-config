# Python

## 環境

- 仮想環境の外で `pip install` しない。`.venv` / `venv` があればそれを有効にして使う
- 依存の管理方法はリポジトリに合わせる (`pyproject.toml` + uv/poetry か `requirements.txt` か)
- **依存を勝手に追加しない。** 必要なら理由を添えて提案する

## 整形とリント

- `ruff` の設定があるリポジトリでは、編集後に `ruff format` と `ruff check --fix` が自動で走る
- `black` / `isort` / `flake8` を使っているリポジトリでは、そちらの設定に従う。
  複数のフォーマッタを混ぜない
- 整形のためだけの差分を、機能の変更と同じコミットに混ぜない

## 書き方

- 公開関数・メソッドには型ヒントを付ける。内部のローカル変数までは不要
- 可変オブジェクト (`[]`, `{}`) をデフォルト引数にしない
- 例外は具体的に捕まえる。`except Exception:` や裸の `except:` を新規に書かない
- パスの操作は `pathlib` を使う。文字列連結でパスを組み立てない
- ログは `print` ではなく `logging` を使う。認証情報や個人情報を出さない
- f-string を SQL の組み立てに使わない。必ずプレースホルダでパラメータを渡す

## テスト

- `pytest` を使うリポジトリでは、テストの命名と配置を既存に合わせる
- 実行: `pytest` / 対象を絞るなら `pytest tests/test_foo.py::test_bar`
- 外部 I/O (ネットワーク、DB、ファイル) はモックするか、既存の fixture を使う
- テストを通すためにプロダクションコードの検証を緩めない
