# サーバー・インフラ (Windows Server / Linux Server)

## 大原則

**設定ファイルの編集と、サーバーへの実行は別のこと。**
ここで扱うのはファイルの編集まで。実際にサーバーへ適用する操作は自動で実行しない。

自動で実行しないもの (手順を提示して人に実行してもらう):

- サービスの起動・停止・再起動 (`systemctl`, `Restart-Service`, `iisreset`)
- デプロイ、リリース、ロールバック
- DB のスキーマ変更、データ更新、マイグレーション実行
- `terraform apply` / `ansible-playbook` の実行 (`plan` / `--check` は可)
- `kubectl apply` / `delete` / `rollout restart`
- 再起動・シャットダウン、ファイアウォールやネットワーク設定の変更

これらの多くはフックで実行前に止まる。止まったら、コマンドを提示して人に渡す。

## 環境の取り違えを防ぐ

- 触る前に、それが本番か検証かローカルかを**必ず確認する**。判断がつかないなら聞く
- ファイル名やディレクトリ名に `prod` / `production` / `本番` が含まれるものは、
  読むだけでも慎重に。書き換えは必ず確認を取る
- 接続先ホスト名・IP・DB 名を書き換えるときは、変更前後を明示して確認を取る

## 秘密情報

- 設定ファイルに認証情報を直接書かない。環境変数か、そのリポジトリが使っている
  シークレット管理の仕組みに載せる
- 既存ファイルに平文の認証情報を見つけたら、**それを引用せずに**「ここに平文の値がある」と報告する
- `.env` / `*.pem` / `*.key` / `*.pfx` / `*.jks` などは読み取りを遮断してある

## Linux

- スクリプトは `set -euo pipefail` で始める
- 変数は必ずクォートする (`"$var"`)。パスに空白が入ると壊れる
- `rm` は対象を明示する。ワイルドカードと変数展開を組み合わせない
- 権限は最小限に。`chmod 777` を書かない
- 冪等に書く。2 回流しても壊れないようにする

## Windows Server

- PowerShell スクリプトは `Set-StrictMode -Version Latest` と `$ErrorActionPreference = 'Stop'`
- パスに空白が入る前提で、必ずクォートするか `&` 演算子で呼ぶ
- レジストリ・IIS・スケジュールタスクの変更は、変更前の値を控えてから行う手順にする
- 文字コードに注意。ログや設定ファイルの読み書きで `-Encoding` を明示する

## コンテナ / CI

- Dockerfile ではベースイメージのタグを固定する (`latest` を使わない)
- ビルド時に秘密情報を `ARG` で渡さない (イメージ履歴に残る)
- CI のワークフローを変更したら、何が変わるかを説明する。
  シークレットを参照する箇所を増やすときは必ず確認を取る
