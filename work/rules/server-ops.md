## 大原則

**設定ファイルの編集と、サーバーへの適用は別のこと。** ここで扱うのはファイルの編集まで。

適用側の操作 (サービスの起動停止、デプロイ、マイグレーション、`terraform apply`、
`kubectl apply`、再起動) はフックが実行前に止める。止まったら、コマンドを提示して人に渡す。

## 環境の取り違えを防ぐ

ここが事故の起点になる。**設定ファイルを触る前に必ず確認する。**

- それが本番か検証かローカルかを確認する。判断がつかないなら聞く
- ファイル名やディレクトリ名に `prod` / `production` / `本番` が含まれるものは、
  読むだけでも慎重に。書き換えは必ず確認を取る
- 接続先ホスト名・IP・DB 名を書き換えるときは、変更前後を明示して確認を取る

## 秘密情報

- 設定ファイルに認証情報を直接書かない。環境変数か、そのリポジトリが使っている
  シークレット管理の仕組みに載せる
- 既存ファイルに平文の認証情報を見つけたら、**それを引用せずに**「ここに平文の値がある」と報告する
- ビルド時に秘密情報を `ARG` で渡さない (イメージ履歴に残る)

## Windows Server

- レジストリ・IIS・スケジュールタスクの変更は、変更前の値を控えてから行う手順にする
- ログや設定ファイルの読み書きで `-Encoding` を明示する (文字化けの原因になる)

## CI

- ワークフローを変更したら、何が変わるかを説明する。
  シークレットを参照する箇所を増やすときは必ず確認を取る
