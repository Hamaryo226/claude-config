# 差分を検証する

対象の差分と完了条件から確認方法を選ぶ。検証・診断だけの依頼ではコードを編集しない。
修正まで承認されていれば、依頼に起因する不具合を直して必要な確認まで続ける。

- コマンドは対象の scripts、wrapper、solution、CI から選ぶ。文言修正に一律の全体 build は不要。
- 行動に関わる変更は関連テストや再現手順で確かめる。期待値を弱めて成功扱いにしない。
- ローカルの使い捨て fixture で完結する確認は進める。本番・外部環境への変更をローカル検証から推認しない。
- 環境エラーとコードエラーを分ける。PATH で見つからないことはホスト PC への未インストールの証拠にならない。
- ユーザーが UI・描画・音声・入力等を確認すると指定した場合、その範囲を未確認として引き継ぐ。
- 非同期フォーマッタ等が動いた場合は、完了後の差分を確認する。

必要な検証が成功し、新たな差分や懸念がなければ終了する。
結果は実行内容・成否・残る未確認を簡潔に報告する。性能は同じ条件の前後値と単位を示し、
build 成功を実動作成功に、静的な文量削減をモデルの品質向上に言い換えない。
