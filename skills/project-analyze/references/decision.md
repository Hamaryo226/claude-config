# 指示を置く場所の判断

判断に必要な固有情報、再利用できる作業知識、既知の失敗を防ぐ制約を残す。
一般論・重複・すぐ陳腐化する一覧は省く。文字数や手順数だけで有用性を決めない。

| 層 | 適する情報 |
| --- | --- |
| AGENTS.md / CLAUDE.md | リポジトリ固有の実行条件、重要な制約、資料を読む条件 |
| rules | 対象 paths に関わるときだけ必要な規約 |
| skills | 特定の依頼で再利用できる判断基準、手順、スクリプト |
| agents | 独立した調査や長い出力の分離に明確な価値がある役割 |
| settings | 当該ランタイムが解釈する権限・フック等の設定 |

## 根拠と適用範囲

- 明示的な規約、実装で確認した事実、観測した慣習、推測を区別する。
- 資料とコードの矛盾は、記述時点と対象範囲を確認する。解決できない仕様判断を勝手に設定へ固定しない。
- 一つの評価の結果を全モデル・全タスクの性質に一般化しない。
- ツールが強制する規約の再説明より、必要な実行コマンドや例外を記す。

## スキルと資料

description は適用される依頼を短く示す。対象技術に触れただけで発火する表現を避ける。
本文は目的と判断基準を中心にし、順序が重要な操作だけ手順を固定する。
資料の内容を本文に複製せず、必要になる条件と Markdown リンクで参照する。
再利用性は過去の回数だけでなく、今後の用途と固有知識から判断する。

スキルを発見・読み込みできることと、副作用を伴う操作の承認は別。
既存の起動設定は維持し、変更が必要ならその理由と対象ランタイムの仕様を確認する。
承認済みの作業をスキル境界だけで拒否せず、依頼範囲と実行権限に従って続ける。

## 既存設定

改善依頼の範囲では、根拠を示して重複の統合や簡略化を実施できる。
調査だけの依頼は提案で止める。結果が変わる未解決の仕様、範囲外の削除や権限拡大は確認する。
ローカル設定や秘密情報をテンプレートに取り込まない。
