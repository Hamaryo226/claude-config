# 複数の境界にまたがる変更を実装する

要求を観測可能な完了条件にして、関連する契約と呼び出し元を追う。
小さな修正に全体調査を要求しない。仕様の未確定点があれば、影響しない作業を進めながら解決する。

必要な境界だけ確認する:

- API / DTO / イベント / ファイル形式: 呼び出し元と後方互換性
- schema / migration / transaction: 既存データ、移行順、失敗時の扱い
- 認可 / 監査 / 設定 / バッチ: 権限、ログ、運用への影響
- UI / 外部連携: 実行可能な確認方法と環境

既存の設計とユーザーの作業を保ち、実装・対応テスト・必要な移行手順を完成させる。
最初の実装案だけで止めず、依頼範囲で発見した不具合は修正して関連検証を行う。
会社の本番適用・デプロイ・migration は人が実行する境界を守る。

検証は完了条件とリスクに応じて選ぶ。関連テストと必要な build 等が成功したら、
新たな根拠なく同じ検証を繰り返さない。UI・音声・入力・外部連携は build 成功と区別する。
ユーザー担当の実機確認は未確認として、再現手順と期待結果を引き継ぐ。
