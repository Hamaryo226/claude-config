# 既存コードから固有の規約を抽出する

通常の実装修正だけでは起動しない。明示的設定を優先し、コードの多数派を設計上の正解と同一視しない。
対象は配置・命名・コメント・ログ・例外・テストのうち、今回の依頼で判断が必要なもの。

- 設定と代表例の選び方は [sampling.md](references/sampling.md)。小さいリポジトリに固定の最低ファイル数を要求しない。
- 数え方に迷う観点だけ [observe.md](references/observe.md) を参照する。定量的な主張には分子・分母・対象範囲・方法を添える。
- 観測の強さと例外は [confidence.md](references/confidence.md) で判断する。設定による規約とコードから推測した慣習を区別する。
- rules の構成が必要なら [output.md](references/output.md)。常時指示と重複させず、対象 paths を絞る。

調査・提案だけなら結果を報告する。生成・改善まで依頼されていれば、根拠と変更方針を短く伝え、
既存の有効な規約を保ちながら編集まで進める。置換量だけを理由に再承認を求めない。
混在や移行中の慣習を勝手に統一せず、設計意図が未確定なら該当部分の判断を求める。

生成後は実例で規約を検算し、paths とリンクを確認する。コメントを調べる場合は
書く場所だけでなく書かない場所も扱う。結果は観測範囲を明示して報告し、コード自体を一括整形しない。
