# 既存コードの流儀を抽出して rules にする

目的は **Sonnet 5 に一般論を教えることではない。** 既存の開発者が書いたコードと自然に馴染む
コードを書かせることだけが成功条件。

`/project-analyze` との違い: あちらは CLAUDE.md / skills / agents / settings まで含めた設定一式を扱う。
こちらは **`.claude/rules/` だけ**を、実コードの実測から作る。両方使うなら先にこちらを回してもよい。

## 原則

1. **推測しない。数える。** 「〜が多いように見える」は根拠にならない。分母と分子を出す
2. **明示的設定 > コードの多数決。** formatter / linter / `.editorconfig` / CI が強制しているなら、
   コードを数える必要はない。設定の方が正解
3. **拮抗しているものは Rule にしない。** 「混在しており規約として確定できない」と報告する
4. **一般論を書かない。** SOLID、可読性、DRY、命名を適切に、null に注意 — 全部書かない。
   Sonnet 5 が既に知っている。書いてよいのは「このシステムではどうするか」だけ
5. **rules を増やすこと自体を目的にしない。** 無意味な細分化をしない

## 進め方

### Phase 1. 機械的な設定を先に読む

@references/sampling.md の「1. 明示的設定」に従う。
`.editorconfig` / formatter / linter / Checkstyle / Spotless / StyleCop / ESLint / Prettier /
コンパイラ設定 / build 設定 / CI をこの順で確認する。

**設定が強制している項目は、コードを数えない。** rules にも書かない
(ツールが直すので、書いても常時トークンを使うだけ)。書くのは「ツールでは直らないが、
このシステムでは統一されていること」だけ。ただし **フォーマッタの実行コマンド**は書く価値がある。

### Phase 2. 構造を掴んでサンプリング

@references/sampling.md の「2. サンプリング」に従う。

- まずディレクトリ構造とモジュール構成を掴む
- 各レイヤ・主要モジュールから代表ファイルを複数選ぶ
- **1〜2 ファイルで断定しない。** 複数モジュール / 複数レイヤ / 最近変更されたコード / テストを含める
- 数えられるものは grep で全数える。読むのは代表ファイルだけでよい

### Phase 3. 観測して数える

@references/observe.md の項目を埋める。各項目に **分子/分母** と **数えた方法** を残す。

観測する領域: コード配置 / コードスタイル / **コメント (最重点)** / ログ・例外 / テスト。

新旧で違うパターンが見えたら、**最近変更されたファイルだけで数え直して比較する**。
「新しいコードは A、古いコードは B」は、それ自体が最も価値のある観測結果。

### Phase 4. 確信度を分類する

@references/confidence.md の閾値で、観測ごとに次のいずれかを付ける。

`明示的規約` / `強い慣習` / `弱い傾向` / `混在` / `不明`

**Rule に書けるのは `明示的規約` と `強い慣習` だけ。** `弱い傾向` は「既存に合わせる」と書くに留める。
`混在` と `不明` は報告するだけで書かない。

### Phase 5. レポートを出して止まる

**ここでファイルを書き始めない。** @references/output.md の形式でレポートを出し、
続けて rules の構成案を出して、ユーザーの了承を待つ。

既存の `.claude/rules/` があれば、各ファイルを
`維持` / `追記候補` / `古い可能性` / `重複` / `実コードと矛盾` に分類して提示する。**勝手に上書きしない。**

### Phase 6. 生成

了承された分だけ書く。テンプレートと分量上限は @references/output.md。

- `paths` フロントマターで対象を限定する。**paths を書けないものは rules にしない**
- CLAUDE.md (プロジェクト / 会社共通 / 個人) に既にあることを繰り返さない
- rules 同士で同じことを書かない
- 各ルールに根拠を残す。書式: `<ルール> (18/19)` のように分子/分母を添える

## 守ること

- 数えていないことを書かない
- 拮抗した観測から片方を選ばない
- コメント方針は「書く場所」だけでなく **「書かない場所」** も書く。これが最も外しやすい
- 生成後、rules に書いた配置ルールで実際のファイルパスが説明できるか 1 件検算する
- コミットはしない
