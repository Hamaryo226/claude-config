# 観測を規約にする判断

割合だけで規約を決めない。対象範囲、件数、例外、設計意図を併記する。

| 分類 | 根拠 | 扱い |
| --- | --- | --- |
| 明示的規約 | 設定・設計方針・CI が明示 | 必要な固有情報を記載する。自動整形内容は重複させない |
| 強い慣習 | 対象の代表例で一貫し、例外の理由も説明できる | 観測範囲と分子/分母を添えて、その範囲の慣習として記載 |
| 弱い傾向 | 少数標本、偏った抽出、説明できない例外 | 傾向として報告し、全体の必須規約にしない |
| 混在・不明 | パターンが割れる、判定できない | 統一しない。必要なら判断を求める |

- 分母と単位を示す。行数、ファイル数、メソッド数を混同しない。
- 生成コードや vendor を除く。全数確認とサンプリングを区別する。
- 9/10 と 90/100 を同じ確実さで扱わない。小さなプロジェクトは小さい範囲の観測として記録できる。
- 多数派でも明示的設定に反するなら、既存コードが規約に追従していない可能性を示す。
- 新旧の差だけで移行中と断定しない。変更履歴や設計方針で移行を確認できた場合、
  新規コードの方針と既存修正での扱いを分け、一括変更を要求しない。

記載するのは固有の判断に効く情報だけ。一般論、他の指示との重複、
自動整形で解決する項目を増やさない。
