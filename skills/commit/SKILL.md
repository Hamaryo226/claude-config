# 対象差分をコミットする

成功条件は、依頼された変更だけがコミットされ、無関係な作業が元の状態で残ること。

- status、staged / unstaged の差分と最近の log から、対象・既存のステージ内容・メッセージ規約を確認する。
- 保護ブランチ (main / master / develop / release、リポジトリ指定のもの) なら、依頼範囲のコミットに必要な作業ブランチを作って進める。ブランチ名の指定や既存規約を優先する。
- 実装と対応テスト・文書は同じ論理単位にできる。分割案は短く伝えて進め、対象や所有者が不明な差分だけ確認する。
- 具体的なパスまたは必要な hunk をステージし、コミット直前に staged diff を確認する。既存の無関係な staged 差分を巻き込んだり、勝手に外したりしない。
- メッセージはリポジトリの規約と履歴に合わせる。フック失敗を --no-verify で回避しない。
- 秘密情報や意図しない生成物が対象に入る場合は、そのコミットを止めて対象を解決する。

コミットだけの依頼なら push しない。「コミットして push」まで依頼されていれば、
同じ承認を再要求せず、remote・送信先・送信するコミットを確認して通常の push まで行う。
他の未送信コミットを含むなど承認範囲が曖昧な場合は確認する。
保護ブランチへの直接 push、force push、履歴改変は行わない。

完了時はコミット ID、変更の要点、実施した検証、残る作業ツリーの状態を伝える。
