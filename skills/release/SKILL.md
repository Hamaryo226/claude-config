# リリースを準備する

依頼された到達点を確認する。ノートの下書き、版更新、コミット、タグ、公開は別の成果物であり、
「準備」だけで push や公開まで許可されたとは扱わない。明示済みの版・操作を再確認しない。

- 現在の branch、差分、既存タグ、直近リリース、配布手順から対象を絞る。無関係な未コミット作業を保持する。
- バージョンは指定値または既存の採番規約に従う。規約から決められない場合は候補と互換性への影響を示し、その間にノートや検証を進める。
- 版の正本と連動するファイルを更新する。日付方式や独自採番に semver を押し付けず、旧バージョン文字列を一括置換しない。
- ノートは既存形式に合わせ、利用者から見た変更と移行上の注意を書く。保存先が決まらなければ会話上で下書きを作る。
- 変更に必要な検証を行い、タグが指すコミットに対象の変更が含まれることを確認する。失敗や未確認を隠してリリース可能と報告しない。
- コミット・タグは依頼範囲で作る。既存タグの移動・上書きは行わない。タグ push が CI の公開を起動する場合、その副作用も確認する。

push・公開が明示的に承認され、会社の運用で実行可能なら、対象 remote・版・成果物を確認して実行する。
会社の本番操作を人が担当する場合は、完成した成果物と正確な手順を引き渡す。
最終報告でローカル準備・タグ作成・push・公開のどこまで終えたかを明示する。
