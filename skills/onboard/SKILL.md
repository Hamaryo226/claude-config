# リポジトリに最小限の指示を用意する

設定の新規導入向け。設計資料と実装の整合性を含む設定監査には project-analyze が適する。

既存の AGENTS.md / CLAUDE.md / .claude/ と、必要な build・test・CI 定義を調べる。
記載するのは、非自明なコマンド、編集禁止領域と再生成方法、固有の制約、既知の落とし穴。
一般論、依存一覧、会社共通設定は繰り返さない。

- AGENTS.md がある場合は共通指示の正本として利用し、CLAUDE.md には必要に応じて @AGENTS.md と Claude 固有の差分だけを書く。参照先が配置先にもあることを確認する。
- 既存ファイルへの導入・改善が依頼されていれば、その範囲を編集する。既存の約束は保ち、挙動を変える矛盾を解決できない場合だけ確認する。
- 固定の行数や全見出しを満たすために情報を足さない。特定の作業でだけ必要な資料には、読む条件とリンクを示す。
- .claude/settings.json は固有の設定が必要な場合だけ作る。既存キーを保持し、不要な権限拡大を避ける。settings.local.json は作らない。
- コマンドは定義元と、実行して確認できた範囲を区別する。文書生成のためだけに本番操作を実行しない。

リンク、設定形式、差分を確認し、変更ファイルと配置後に必要な作業を伝える。
分析・提案だけの依頼なら編集しない。コミット等の追加依頼はその承認範囲で続ける。
