# Pull Request を作成・更新する

依頼が本文案だけなら案を返す。作成・更新まで依頼されていれば、その範囲で完了させる。
既に得た同じ範囲の承認を、本文の提示後に再要求しない。

- branch、remote、base、既存 PR、作業ツリーを確認する。base の指定がなければリポジトリのデフォルトを確認する。
- PR はコミット済み差分を対象にする。無関係な未コミット変更があるだけで停止・stash しない。依頼対象が未コミットなら、含める権限と範囲を確認する。
- base との差分と関連する検証結果を読み、問題と変更後の挙動が分かる本文にする。テンプレートとチームの言語・タイトル規約を優先し、なければ日本語で簡潔に書く。
- 本文には実施済みの確認と必要な未確認事項を載せる。小さい変更に固定の多段見出しを要求しない。
- 既存 PR が対象なら重複作成せず、更新依頼の範囲で扱う。状態確認だけの依頼では更新しない。
- 公開前に送信先とコミット範囲を確認する。未 push の場合も、依頼・既存の承認が push を含むか確認し、含まれなければ本文と差分を整えた段階で判断を求める。

gh を使う場合、本文は一時ファイルから --body-file で渡す。作成・更新後に URL と内容を確認する。
レビュアーやラベルを推測で追加しない。merge の追加依頼がある場合は、別操作として
承認範囲・CI・ブランチ規約を確認する。このスキル自体は merge を承認しない。
